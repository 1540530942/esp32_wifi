# 2026-09-16 · E1 的「收敛 < 1s」一直是平凡为真

## 起因

T3.1 那次教训之后,我去筛「看起来通过、底下压着未验证假设」的判据。
最可疑的是 E1 的收敛时间:**四档音量全部报 `convergence_s=0.0`**。
一个恒为 0 的指标,多半根本没在测。

## 确实没在测

```c
player->play_wav_url(...);                    // 开始播
if (settle > 0) vTaskDelay(settle * 1000);    // 先播 settle 秒
afe_capture_begin(...);                       // 才开始录
```

E1 用 `settle=3`。**滤波器在第一个样本落盘之前已经自适应了 3 秒。**
收敛曲线自然从高位起步,`convergence_s=0.0` 的意思只是
"开录时早就收敛完了"——**它从没回答过"收敛需要多久"。**

## 真测出来的结果

改用 `--settle 0`,让采集从播放第一刻开始:

| | 收敛 | 前 2.5s 的 ERLE 曲线（每 100ms） |
|---|---|---|
| 热态 | **0.6s** | 15.7 → 44.1 → 14.2 → 11.4 → 23.2 → 32.4 → **47.7** → 55.4 → … |
| **冷态（重启后首播）** | **0.5s** | 18.9 → 19.3 → 40.5 → 24.0 → 37.4 → **56.4** → 59.1 → … |

**判据 <1s 真实通过**,冷热两种条件下都过。曲线也终于看得见自适应过程:
前 0.4 秒在 11~23 dB 挣扎,0.5–0.6 秒爬到 47 dB 以上并稳住。

冷态特地重启后测,因为判据关心的是最坏情况,而热态的滤波器可能还留着上一轮的状态。

## 加了守卫，防止再犯

`analyse()` 现在接收固件侧的 settle 值。`settle>0` 时收敛记为 **不可测**
并附说明,而不是留一个读起来像满分的 `0.0`:

```json
"convergence_s": null,
"convergence_note": "不可测：固件先播了 3s 才开始录音，滤波器在开录前已收敛。要测收敛请用 --settle 0。"
```

**这比修好这一次更重要。** 一个恒为 0 的"通过"不会有人去查,
它会一直待在验收表里。让它显式说"我测不了",下一个人才会去用对的参数重测。

## 今天第二次同类问题

- T3.1:`silence_frames=20` 按 16ms 帧算成 320ms,实际帧是 32ms,真值 640ms
- E1 收敛:`settle=3` 让收敛恒为 0.0

两次都是**指标本身没错,错在它度量的东西和判据问的不是同一件事**,
而且都以"通过"的面貌在验收表里待了很久。

# 2026-09-17 · 门限尾巴累积到 50 段：150 站得住，但论证的弱侧换了一边

## 累积数据（门限 150，4 次浸泡）

```
50 段播放，被切 0 段
每轮 AFE 输出峰值：中位 30   p90 73   p95 102   p99 140   最大 140

门限 100 -> 3/50 越过 (6.0%)
门限 120 -> 1/50 越过 (2.0%)
门限 150 -> 0/50 越过 (0.0%)
```

这解决了上一条记录里的问题:**不再用单次浸泡的极值下结论**。
两次单样本极值分别是 94 和 140,而 50 段汇总后 p99 = 140、max = 140——
**140 不是运气,是尾巴的真实位置**,而 94 确实只是抽样偏低。

## 但我差点犯一个镜像的错误

按这组数,机器人尾巴 p99=140、人声最小 357,几何中点约 224,
看起来门限该从 150 往上挪到 200–250,给机器人侧更多余量。

**不能这么做,理由和我上一条批评自己的完全一样。**

> **357 也是一个样本最小值,不是人声的下界。**

它只来自 **15 个发声窗口**,而且全部是树莓派固定位置、固定音量。
我上一条刚写过"拿样本极值当总体上界是错的",现在拿 357 当人声下界去挪门限,
就是同一个错误照镜子。

**论证的强弱侧换边了**:机器人那侧 n=50、刻画得还行;
**人声那侧 n=15,现在是更弱的一半。**

## 真人是未测条件

树莓派位置固定、音量固定。真人说话**距离会变、音量会变**,
更远或更轻的一句完全可能低于 357。这是这套装置**测不出来**的东西——
不是数据不够多,是被测对象不在场。

## 结论

- **门限 150 就现有证据站得住**:机器人侧 0/50 越过,真打断侧
  alpha/beta 8/8 触发、E4 7/8 触发,都在这个门限下测的
- **不挪门限**。要挪必须先把人声侧的分布补厚,而补厚它需要真人、
  在不同距离和音量下说话
- 机器人侧继续累积(每次浸泡自动追加到 `docs/logs/e5_maxima.jsonl`,
  `tools/aec_bench/e5_tail.py` 汇总)

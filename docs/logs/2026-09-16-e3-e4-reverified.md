# 2026-09-16 · E3 / E4 用正确编排重测

两项都依赖树莓派时序,而那条路径(任务队列,下发到出声约 8s)已被证明会污染测量。
改成 ssh 直发 `aplay`(<1s)后重做。

## E4 —— 打断延迟

```
打断触发 10/10（7 次配上咔哒可计时，3 次打断跑赢咔哒、无法计时）
可计时样本: [119, 138, 141, 142, 146, 154, 155]
中位 142 ms  最小 119 ms  最大 155 ms   判据 <200ms -> 及格
真·漏触发 0 次
```

**之前那个 3–4.6 秒的"双峰尾巴"消失了**,证实它是队列延迟的产物,不是慢检测器。

判定逻辑也改了:「click detected but no barge-in」不再算作废,而是查播放命令有没有
提前以 `failed|stage=wav_playback` 结束。**打断跑赢咔哒是常态**(打断在第一帧合格语音
就触发,咔哒检测器要先满足包络比值),那些是**成功但没配上时间戳**,不是失败。
而且它们如果算进来只会把中位数**拉低**,不是藏起来的慢样本。

## E3 —— 双讲（核心）

打断做好之后 E3 反而跑不了:机器人一被插话就停,双讲持续不到 150ms。
加了 `aec_capture` 的 `mute_bargein` 参数——**只统计不执行**,让双讲撑满整个窗口。
这是测量辅助不是产品模式,并且在**每一条退出路径**上都清掉
(包括两处早退 return,漏掉就等于静默关掉打断功能)。

机器人播 turn04,第 6s 起树莓派播 turn05,重叠约 4s。三路逐秒 RMS:

| | 0–3s | **4–8s（双讲）** | 9–15s |
|---|---|---|---|
| reference 回采 | -25~-39 | -28~-30 | -24~-36 |
| mic_raw 麦克风 | -34~-52 | -31~-37 | -30~-49 |
| **clean AFE 输出** | **-81~-90** | **-38~-45** | **-72~-84** |

机器人独播时 AFE 输出压到 -81~-90 dBFS,树莓派一开口跳到 -38~-45,**相差 40 dB**。

### ASR 判读（判据是"可辨"，不是电平）

| 片段 | ASR |
|---|---|
| AFE 输出 · 机器人独播 | **空** |
| 原始麦克风 · 双讲段 | 「与人沿溪而行,偶然发现桃花林,并进入与世隔绝的桃花。」← **机器人的内容** |
| **AFE 输出 · 双讲段** | 「对的,这是我喜欢的陶渊明诗人,你来背诵另外一首。」← **人的内容** |

**同一时刻同一段音频:麦克风里 ASR 听到机器人,AFE 输出里 ASR 听到人。**
回声不是被压低,是被换掉了。机器人独播段转写为空,顺带在同一份采集里坐实了 E2。

### 一个容易误读的数

这次采集报 `erle_full_db=11.09`,远低于单讲时的 38–51 dB。**这不是退化**:
ERLE 的分母是 AFE 输出功率,而双讲时那里面**本来就应该有人声**。
把该留住的信号算进"没消掉的回声",数自然难看。**E1 才是 ERLE 的判据场景,
双讲段不该用 ERLE 判。**

## 旁证

E3 还有一个独立佐证:**打断触发率 100%**。打断要求 `clean_rms ≥ 40` 且 VAD 判为语音,
如果双讲时人声被一起压没了,打断一次也触发不了。
门限计数器在那些窗口里报的 `max_rms` 是 294–831,对着门限 40。

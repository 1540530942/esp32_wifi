# 2026-09-16 · v83 回放修复：用房间麦克风验成

昨晚两个故障(回放太小声 / 回放完全没声)的修复在 v83 里,但一直没验过。
今天用**树莓派一人分饰两角**验证:既当插话者,又当房间见证人全程录音。

## 为什么要房间录音

设备报告 `replayed=1` 只说明**它往编解码器写了采样**。
昨晚正是"命令报成功、实际一声没出"。**要判"听不听得见",证人必须是设备之外的麦克风。**

## 结果：通过

| 房间录音 | 电平 | 是什么 |
|---|---|---|
| 3–7s | -29.6 ~ -42 dBFS | 机器人播 turn06 |
| 9–14s | -2.5 ~ -3.8 dBFS | 树莓派插话（喇叭紧贴自己麦克风，故极响） |
| **16–19s** | **-27.4 ~ -32.0 dBFS** | **回放** |
| 20s+ | -46（静音） | 结束 |

设备侧:

```
spoke=7745ms interrupted rec=4623ms samples=74240 peak=3870 gain=4.2x replayed=1
```

**判据:回放 -27.4 dBFS vs 机器人自己的话 -29.6 dBFS,回放还高 +2.3 dB。**
对比昨晚失败那次:插话之后是一整片 -46 dBFS 的死寂。

拿同一段录音里的两段互比,是为了**把喇叭音量、距离、麦克风增益这些变量全约掉**,
只留下真正要问的那个问题。

## 第一轮没验成，原因在编排不在固件

第一次跑出来是 `spoke=3876ms rec=782ms peak=73`,近乎空录。对时间线才看明白:

**树莓派的插话来晚了 8 秒。** 走 `/action/api/tasks` 下发,从下发到出声约 8s,
而机器人在那之前就被**别的声音**打断了(房间里有动静)。所以那一轮
**测的根本不是一次打断**。

改用 ssh 直接 `aplay`,下达到出声 <1s。改完 `spoke=7745ms`,正对上我设定的
6.0s 插话时刻——**这个数字本身就是"这次确实是树莓派打断的"的证据**。

顺带确认:同一块 USB 声卡可以边录边放(card 2),不冲突。

## 自动判语也错过一次

第一版判语用绝对门限 -25 dBFS 找"响亮段",结果:

- 机器人说话 -29.6 dBFS → **没被认出来**,打印"没找到机器人说话段"
- 回放 -27.4 dBFS → **没被认出来**
- 唯一超过 -25 的是树莓派自己(-2.5 dBFS,因为它的喇叭贴着它的麦克风)

于是它把树莓派的尾音当成了回放。**一个贴着麦克风的声源,和两个隔着房间的声源,
不能用同一条绝对线去分。** 改成相对房间底噪:门限 = 底噪 + 12 dB
(实测底噪 -46.1 → 门限 -34.1),三段就都分对了。

**这是今天第二次"演示是好的、测量是坏的"**——昨晚是按文件名找回放命令找不到,
今天是按绝对电平找回放段找不到。

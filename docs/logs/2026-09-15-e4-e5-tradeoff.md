# 2026-09-15 · E4 与 E5 的冲突：当前 AFE 配置下无法同时达标

## 结论

**在 esp-sr 的 WebRTC VAD 下，E4（打断延迟 <200ms）和 E5（误打断 0 次）
无法同时满足。** 这不是调参没调到，是三组实测数据划出的边界：

| 配置 | E4 中位 | E5（完整 127s，串口判定） |
|---|---|---|
| `vad_mode`3 + `min_speech`48 | **127ms** ✅ | ❌ 误触发 |
| `vad_mode`3 + `min_speech`64 | 193ms | ❌ **串口确证 2 次真实打断** |
| `vad_mode`4 + `min_speech`64 | 232ms ❌ | ✅ **0 次** |

选 **mode 4 + 64ms** 作为出厂配置。理由：E5 失败意味着机器人**不断打断自己**，
用户每次对话都会遇到；E4 232ms 对 200ms 是 16% 超出，感知弱得多。
**这是一个有代价的选择，不是达标。**

## 延迟预算（mode 4 + 64ms，实测 232ms）

| 环节 | 耗时 | 来源 |
|---|---|---|
| `vad_min_speech_ms` | 64ms | 配置（esp-sr 默认 128ms） |
| 1 帧叠加确认 | 16ms | 配置 |
| 停播 | 24ms | T3.2 实测 |
| **AFE 流水线 + 判决** | **~128ms** | 差值，**不可压缩** |

任务书给 "AFE + VAD" 的预算是 50ms，**实际这一段就要 ~128ms**。

## 试过且失败的降延迟手段

1. **原始麦克风提前触发路径**（v60–v66，七个版本）
   离线仿真 28 组参数全不可行：机器人自己说话时 ch0/ch1 比值的波动
   （非线性、房间模态、帧间偏斜）大于插话人声带来的增量。**整条路无解**，已禁用。
   脚本 `early_bargein_sim.py` 保留，让否定结论可复现。

2. **`vad_mode` 3→4**（v72）
   E5 从失败变通过，**但 E4 从 193ms 涨到 232ms**。我原以为"改判决门限不花时间"，
   **这个预判是错的**：更保守的判决需要更多证据，本身更慢。

3. **`vad_delay_ms` 128→32**（v73）
   E4 变成 246ms / 1307ms，**更差且极不稳定**。这个字段是语音起始的
   **前向缓存**，不是判决延迟——esp-sr 原话「if you find vad cache can not
   cover all speech, please **increase** this value」。调小它让 VAD 漏掉起音，
   反而要等更多语音才敢触发。已改回 128。

   **两个 128ms 默认值，一个是真凶一个是巧合**：`vad_min_speech_ms` 确实值那
   128ms 且改对了；`vad_delay_ms` 数字相同但性质完全不同。

4. **加大 onset grace**（900→1500，v69）
   无效。误触发发生在播放 1.4–6.9 秒处，远在任何 grace 之后。

## 唯一可能解开的路：神经网络 VAD（需要授权）

`vad_energy_threshold` 是**按电平**拒绝的门限——残余回声比真人声弱，
电平正是对的区分维度，**而且电平判断不花时间**，不会像 `vad_mode` 那样牺牲 E4。

但它的注释写明「only applied when a **vad model** is used」，而本工程
`vad_model_name` 为 NULL、走 WebRTC VAD。启用 `vadnet1_medium` 需要 model 分区，
而 `partitions.csv` 里没有——**加分区等于重写分区表**，`WORKING.md` 要求明确授权，
且出错需要物理恢复（我无法执行）。

**这一步没有做，等授权。**

## 顺带记录：命令下发是分钟级延迟，不是丢失

多次测量里出现的"命令未送达"，串口证明是**送达太晚**：设备执行了一条早已被脚本
判定为丢失的播放命令（`c-414e55`，turn02 完整播完）。测量脚本的等待窗口已从
60s 放宽到 180s。

**这对实时机器人本身也是问题**，不只是测量干扰——一条打断或播放指令延迟几分钟
才生效，用户侧就是"机器人过一会儿突然自己动了"。与 retained 重放
（见 `2026-09-15-retained-commands-broke-e5.md`）是两个独立的问题，**都未修复**。

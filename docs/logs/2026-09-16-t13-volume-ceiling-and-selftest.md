# 2026-09-16 · T1.3 复核：工作上限测出来了，并补上开机自检

## T1.3 复核

判据:**音量推到实际工作上限,播真实 TTS,抓 ch1 峰值(不是 RMS),落在 -12 ~ -6 dBFS。**

验收表里记的是 -9.0 dBFS,但我今天量到 vol80 是 -10~-13、vol100 是 -1.9,三个数对不上。
用归档采集里的 `reference.wav` 离线算真实峰值(而不是运行时的估计),
在工作音量 80 下:

| 采集 | ch1 峰值 |
|---|---|
| E2 turn04 ×2 | **-9.0 dBFS** |
| E2 turn10 | -10.3 dBFS |
| E3 双讲 | -9.0 dBFS |

**-9.0 可复现,在判据带内。** (E2b 那几次是 -84.3,因为机器人根本没播,回采本就该静音。)

## 「实际工作上限」到底是多少

判据说"推到工作上限",但上限从没定义过。扫一遍:

| 音量 | ch1 峰值 | 削顶累计 | |
|---|---|---|---|
| 60 | -19.0 | 0 | 偏低 |
| 70 | -14.0 | 0 | 偏低 |
| **80** | **-9.0** | 0 | ✅ 带内 |
| **85** | **-6.4** | 0 | ✅ 带内（贴边） |
| 90 | -3.9 | 0 | 偏高 |
| 100 | -1.9 | **+5** | ❌ 必须降 |

**判据带对应音量 80–85,这就是工作上限。** 超过 90,AEC 依赖的线性假设开始破;
到 100 削顶计数真的动了。

## 开机自检（清单里最后一条未做的建议）

清单:「建议加:开机自检——播一小段信号,检查 ch1 峰值是否在合理区间,超了打 warning」。

**不需要额外放测试音**:开机播报本来就在通过同一只喇叭出声,拿它当激励即可。
播报前清一次峰值,播完读一次,判档后进心跳(`ref_selftest`)。

判档刻意比 T1.3 宽(-20 ~ -3):**它要抓的是装配/接线坏掉,不是校准漂移。**

### 为什么值得加

这个故障**是静默的**。回采过热会削顶,破坏 AEC 依赖的线性;过轻则滤波器没东西可用。
两种情况下房间里听着都正常,**唯一症状是"等真有人跟它说话时打断不工作"**——
而那要等到实际使用中才会被发现,那时已经没人会联想到回采电平。

## 这轮的模式

和 T3.1、E1 收敛是同一类:**判据里有个量我从没实测过**(帧长 / 收敛起点 / 工作上限),
于是拿一个看起来合理的值代替。区别是这次没出错——-9.0 是对的——
但"工作上限"始终是空的,直到扫出那张表才有意义。
